# Dev Pipeline -- Issues #137 and #138

## Phase 1: Problem Statement

**Issue #137 -- Review detail shows no fields when auto-accepted**

When `autoAccepted=true` (status=`completed`, all fields >= 0.90 confidence), the review detail
panel showed "All fields reviewed" but the extracted fields section appeared blank. Root cause:
the textarea for each field used `disabled={isFinalized}`, and while the values were technically
present, the UX was misleading -- no clear visual indication that this was a read-only completed
review, and the disabled textarea styling made it hard to see values.

**Issue #138 -- Similar cases tree: use interviewDate instead of uploadedAt**

The `CaseTimeline` component displayed `doc.createdAt` (document upload timestamp) as the date
on each document card. This is meaningless for case history; the relevant date is `interviewDate`
from extracted fields (added in PR #131). The `CaseDocumentItem.fields` already contains
`interviewDate` when extracted; the fix is purely frontend.

## Phase 2: Solution Space

**#137:** Replace `<textarea disabled>` with a `<p>` element when `isFinalized=true`. Also:
- Add `isAutoAccepted` flag (status === 3 or 'Completed')
- Show "Auto-accepted — all fields high confidence" instead of generic "All fields reviewed"
- Slight background change (`bg-slate-50`) on field cards in read-only state

**#138:** In `CaseTimeline.map()`, look for `interviewDate` in `doc.fields` (case-insensitive),
parse it, and use it as `displayDate` if valid. Suppress the time component when using
`interviewDate` (dates from forms have no meaningful time). Fall back to `doc.createdAt`.

## Phase 3: Execute

### Changes

- `apps/web/src/pages/ReviewerDashboard.tsx`
  - Added `isAutoAccepted` constant in `ReviewDetail`
  - Changed status subtitle to "Auto-accepted — all fields high confidence" when auto-accepted
