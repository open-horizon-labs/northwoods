# Dev Pipeline -- Extraction: store all discovered fields + add interviewDate to all templates + reprocess
**Issue:** #131
**PR:** (filled in Phase 3)
**Started:** 2026-03-28

## Phase 1: Problem Statement

**Problem:** Extraction discards non-schema fields. Re-extraction is expensive; storage is cheap. We need to store everything the model finds, overlaid with schema validation.

**Acceptance Criteria (from issue):**
- `extracted_fields` has `is_discovered BOOLEAN NOT NULL DEFAULT false` column
- Vision prompt returns all fields found on the form, not just schema fields
- Schema fields still go through existing confidence/review/status logic unchanged
- Discovered fields stored with `is_discovered = true`, `requires_review = false`
- `interviewDate` added to all 4 template schemas (type: date, required: false)
- `case_profiles.search_text` includes discovered field values
- Review detail shows discovered fields in a collapsible "Additional fields" section
- Admin/dev endpoint or migration to requeue existing documents for reprocessing

## Phase 2: Solution Space

**Selected approach:** Option C — open-ended prompt + schema overlay.

- Change vision prompt to "extract ALL fields + schema fields"
- Provider marks discovered keys with `is_discovered=true` in metadata
- `ExtractionPipelineService.RunExtractionPipeline` returns `(schemaFields, discoveredFields)` tuple
- Discovered fields stored with `is_discovered = true`, `requires_review = false`, don't affect document status
- `interviewDate` added to all 4 template schemas via M006 migration + SeedTemplatesSql update
- Frontend shows discovered fields in collapsible "Additional fields" section (read-only with confidence badge)
- `POST /admin/reprocess` endpoint resets documents to `uploaded` status scoped to eligible docs only
